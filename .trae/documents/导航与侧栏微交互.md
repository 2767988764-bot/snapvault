# 顶部导航与侧栏微交互

## Context

用户给出了一组 7 条微交互规格（顶部导航选中项滑移 / ReviewBadge 弹跳 / ScanButton hover 按下 / 左侧栏 active pill 滑移 / 文件夹树展开折叠 / 侧栏折叠 / 图标 hover）。

调研后发现两个结构性障碍，并已与用户确认处理方式：

1. **顶部导航在 9 个 view 里各有一份完全重复的内联副本**（HomeView、DocumentDetailView、LibraryHeroView、LibraryPulledView、LibrarySearchView、ReviewQueueView、ScanImportView、ScanResultView、SettingsView），「当前页高亮谁」由内联 `background-color: #2B5BD7` 硬编码。`App.vue` 只有 `<router-view />`。因此**跨路由切换时导航整块重挂**，规格要求的「指示块 180ms 滑移到新项」在真机上根本看不到。
   → 用户选择：**把 TopNav 提升到 App.vue 常驻**（单份实例），各页留 64px 占位。
2. 规格说「侧栏折叠 300px↔64px」，但 Library 侧栏现状是 240px 固定宽 + 0.2s/0.7s 两段式缩放弹入（`LibraryView.vue` 已实现）。
   → 用户选择：**本次不做侧栏折叠**（保留现有弹入动画，不新增折叠态）。因此侧栏只做：分类 active pill 滑移、文件夹树展开折叠、图标 hover。

另外用户确认：文件夹树**新增占位子项**并实现完整展开动画；ReviewBadge **引入可变计数 + 演示入口**。

预期结果：跨路由时顶部导航常驻、激活指示块平滑滑移，导航/侧栏各处 hover 与展开动效按规格落地，且不破坏现有 Library 拉条、搜索聚焦、拖放等已验收交互。

## 一、顶部导航常驻化

### 1.1 新建 `src/components/TopNav.vue`
从现有内联导航 1:1 搬运，保留全部 `data-pencil-name`（`TopNav` / `NavLeft` / `Brand` / `NavLinks` / `NavItem/*` / `NavLabel/*` / `ReviewBadge` / `ReviewBadgeText` / `ScanButton` / `ScanIcon` / `ScanLabel`），保证 pencil 语义与逐像素样式不变。

- **根定位**：`position: fixed; top: 0; left: max(0px, calc(50% - 720px)); width: 1440px; z-index: 80;`
  - 用 `left: max(0px, calc(50% - 720px))` 复刻 `.page-root { margin: 0 auto }` 的行为：视口 ≥1440 时与 page-root 左缘对齐；<1440 时 page-root 左缘贴 0，导航同样贴 0（若用 `translateX(-50%)` 会在窄视口错位）。
  - **z-index 取 80**：全站现有最大 z-index 是 `ScanImportView.vue` 的 `.dz-flyers`（`position:fixed`，z-index 90，拖放飞入缩略图），导航需低于它以不遮挡飞入动画，同时高于搜索面板（60）、`sf-raised`（50）、侧栏（6）、拉条（4）。
- **active 由路由推导**（复刻现有行为，不改变任何页面的高亮结果）：
  - `/home` → `home`；`/library`、`/library-search`、`/document-detail` → `library`；`/review-queue` → `review`；`/scan-import`、`/scan-result`、`/settings` → **无 active**（现状这三页没有任何高亮项）。
- 三个 NavItem 用配置数组 `v-for` 渲染（`{ key, label, to, badge }`，仅 review 带 `badge`），三个容器 ref 组成数组供量测。
- 导航项自身背景一律置透明（激活背景改由滑移指示块承担），hover 背景用 `#FFFFFF14`。

### 1.2 改造 `src/App.vue`
```vue
<template>
  <TopNav v-if="showNav" />
  <router-view />
</template>
```
- `showNav` 按 `route.path` **白名单**：`/home` `/library` `/library-search` `/document-detail` `/review-queue` `/scan-import` `/scan-result` `/settings`。`/login` `/states` `/overview` 不渲染（与现状一致）。
- 不用「按 view 数量」列举，直接按 path 配置，避免漏掉 `/library`（LibraryHeroView 的宿主路由）。

### 1.3 9 个 view 里移除内联导航
- **7 个导航可见页**（HomeView、DocumentDetailView、LibraryHeroView、ReviewQueueView、ScanImportView、ScanResultView、SettingsView）：把整段 `<div data-pencil-name="TopNav" …>…</div>` 替换为
  `<div data-pencil-name="TopNavSpacer" style="height: 64px; flex-shrink: 0; width: 100%"></div>`
  （已确认这些页面的 `.page-root` 均为 `display:flex; flex-direction:column; height:900px; overflow:hidden; width:1440px; position:relative`，且 TopNav 之后的兄弟节点都是正常 flex 流 —— HomeContent / 各 `flex:1` 容器 / ResultBar / DetailBar —— 故 64px 占位可精确保持布局不位移。）
- **LibraryPulledView**：TopNav 原本就被 `LibraryView` 的 `:deep` 规则 `display:none`（占位 0），且该视图**只能**经 `/library` 内嵌进入 → **直接删除**导航块，不加占位。找不到路由 `/library-pulled`。
- **LibrarySearchView（双上下文，须特别处理）**：既可被 `/library` 内嵌（此时 TopNav 被 `:deep` 隐藏），也可经 `/library-search` **独立直达**（此时导航是正常流首项、会显示）。→ 替换为 `TopNavSpacer`，并**扩展** `LibraryView.vue` 的隐藏规则，使其在内嵌时把占位一起隐藏：
  ```css
  .pulled-layer :deep([data-pencil-name="TopNav"]),
  .pulled-layer :deep([data-pencil-name="TopNavSpacer"]) { display: none !important; }
  ```
  这样内嵌时占位为 0（与现状一致），独立直达时 64px 正常占位。
- 顺带更新 `LibraryView.vue` L332 的注释（TopNav 已不在这两个视图内）。

## 二、导航微交互

### 2.1 激活指示块滑移（180ms）
- `NavLinks` 内联 style 追加 `position: relative`（当前 `position: static`，无法承载绝对定位子元素）。
- 新增绝对定位的 `.nav-indicator`：`position:absolute; top:4px; height:28px; left:0; width:0; background:var(--sv-accent); border-radius:10px; transition: transform 180ms ease, width 180ms ease, opacity 150ms ease; z-index:0;`（NavItem 加 `position:relative; z-index:1` 保证文字在指示块之上）。
- 量测：`onMounted` + `watch(active)` + `nextTick`，用 `getBoundingClientRect()` 差值计算 `translateX = itemRect.left - linksRect.left - links.clientLeft`（**不要用 `offsetLeft`**：它含 `NavLinks` 的 1px border，会整体左偏 1px），宽度取 `itemRect.width`。
- 字体异步加载会改变文字宽度 → 在 `document.fonts.ready` 后与 `ResizeObserver(NavLinks)` 触发时重测。
- 无 active 时（scan/settings 页）指示块 `opacity: 0`，避免停在上一个位置。

### 2.2 导航项 hover 背景淡入（120ms）
`.nav-item { transition: background-color 120ms ease }`，hover → `background-color: rgba(255,255,255,.08)`。因内联背景为 `#FFFFFF00`，需 `!important` 覆盖。

### 2.3 ScanButton hover / 按下
```css
[data-pencil-name="ScanButton"] {
  transition: background-color 180ms ease, transform 180ms ease;
}
[data-pencil-name="ScanButton"]:hover {
  background-color: var(--sv-accent-hover) !important; /* #1F49B8 渐变加深 */
  transform: translateY(-2px);
}
[data-pencil-name="ScanButton"]:active { transform: translateY(1px); }
```
（内联 `background-color:#2B5BD7` 优先级高于 scoped class，必须 `!important`。）

### 2.4 ReviewBadge 计数弹跳（400ms，非常驻）
- 新建 `src/composables/useReviewCount.js`：`export const reviewCount = ref(3)` + `bumpReviewCount(delta = 1)`，供导航与侧栏共享（与项目既有 composable 风格一致，不引入 Pinia store）。
- `TopNav.vue` 的 `ReviewBadgeText` 渲染 `{{ reviewCount }}`；`watch(reviewCount)` 时切换一次性 class，触发
  `@keyframes badge-bounce { 0%{transform:scale(1)} 40%{transform:scale(1.15)} 100%{transform:scale(1)} }` 400ms。
- 「非常驻」：动画结束即移除 class，元素上不残留常驻 `transform`（避免常驻合成层）。
- **演示入口**：仅 DEV 环境渲染一个小型浮层触发器（`v-if="import.meta.env.DEV"`，点击 +1 / -1），用于真实触发并验证弹跳；生产构建不出现。

## 三、侧栏微交互（全部在 `src/views/LibrarySidebarPanel.vue`）

### 3.1 分类选中项 active pill 滑移（180ms）
- 把现有 5 个 `NavRow` 包进 `position: relative` 的 `.nav-group`，组内放绝对定位 `.nav-pill`。
- 5 个 `NavRow` 加 `@click="activeNav = i"` 与 `:class="{ 'is-active': activeNav === i }"`；`activeNav` 默认 `0`（All Documents，与现设计稿一致）。
- `.nav-pill` 位置/高度由各 NavRow 的 `getBoundingClientRect()` 差值量测，`transition: transform 180ms ease, height 180ms ease`。
- 颜色态：现有激活态是**内联**写死在第一个 NavRow 上的 `background-color:#E7EDFC` 及 accent 色 icon/label/count。→ 用 scoped CSS 归零并改由状态类驱动：`[data-pencil-name="NavRow"]{background-color:transparent !important}`；`.is-active` 下的 `NavLabel/NavCount` 用 `color: var(--sv-accent) !important`，`NavIcon path` 用 `fill: var(--sv-accent)`（CSS `fill` 可覆盖 svg 的 `fill` presentation attribute，无需 `!important`）。
- 交互仅切换视觉选中态（这些是库内筛选项，无路由，不新增筛选逻辑）。

### 3.2 文件夹树展开 / 折叠
- `FolderRow` 加 `data-clickable` 与 `@click="toggleFolder(name)"`，`folders` 状态记录展开集合（默认全部折叠，保持现有静态视觉）。
- 每个文件夹改为「`FolderRow` + `.folder-children`」两块；`.folder-children` 用免测高方案：
  ```css
  .folder-children { display:grid; grid-template-rows:0fr; transition: grid-template-rows 250ms cubic-bezier(0.16,1,0.3,1); }
  .folder-children > .fc-clip { min-height:0; overflow:hidden; }
  .folder.open .folder-children { grid-template-rows: 1fr; }
  ```
- `Chevron` 加 `:class="{ open }"`：`transition: transform 150ms ease`，展开时 `rotate(90deg)`。
- 子项（新增占位数据）：Research → Papers / Datasets / Notes；Courses → Computer Vision / NLP；Projects → SnapVault；Personal → Receipts。子项样式沿用侧栏小号文字（`Instrument Sans` 13px，#59606E，左侧缩进对齐 FolderName）。
- 子项入场：展开时 `animation: fc-fade-in 200ms ease both` + `animationDelay: index * 40ms`（淡入 + 轻微上移）；用 `:key` 或 class 切换强制重放入场动画。

### 3.3 图标 hover（150ms 缩放 1.05 + 120ms 变深）
作用范围限定在 **TopNav 与 LibrarySidebarPanel** 两处（规格所在语境），不做全站图标，避免波及所有 view：
```css
[data-pencil-name$="Icon"], [data-pencil-name="Chevron"] { transition: transform 150ms ease; }
[data-pencil-name$="Icon"]:hover, [data-pencil-name="Chevron"]:hover { transform: scale(1.05); }
[data-pencil-name$="Icon"]:hover path, [data-pencil-name="Chevron"]:hover path {
  fill: var(--sv-ink); transition: fill 120ms ease;
}
```

## 四、动效令牌与降级

- 在 `src/styles/tokens.css` 追加动效 token，替代散落的魔法数字：
  `--sv-dur-fast: 120ms; --sv-dur-icon: 150ms; --sv-dur-move: 180ms; --sv-dur-tree: 250ms; --sv-dur-badge: 400ms; --sv-ease-out: cubic-bezier(0.16,1,0.3,1);`
- 追加全局降级（全项目当前无 `prefers-reduced-motion` 处理）：
  ```css
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after { animation-duration: .01ms !important; transition-duration: .01ms !important; }
  }
  ```
- 既有 `SNAP_MS`(560) / `MORPH_MS`(200) / `PANEL_MS`(700) 保持不变，不动已验收的 Library 动效。

2. 启动 dev server（注意 5173/5174 被另一个项目 `E:\snapvalut\frontend` 占用，需 `npm run dev -- --port 5199 --strictPort`），逐页目视：
